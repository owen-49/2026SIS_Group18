# Project-facing naming

Use neutral project or task names in all new work. Do not add assistant/tool
branding or attribution to source code, documentation, commit messages, pull
request titles/descriptions/comments, or work reports.

Use task-based branch prefixes such as `backend/`, `feature/`, `fix/`, or `deploy/`.
The deployment-preparation branch is `backend/deployment-prep`.

Apply this convention to future project work without rewriting existing Git
history, renaming unrelated branches, or changing application-managed system
paths. Preserve user changes when editing existing work.
