## Slide 2 — Project Scope and Users (What and Who)

### 2.1 The Problem: 我们发现了什么问题？

```
┌─────────────────────────────────────────────────────────────────┐
│                                                                 │
│   📱 全球超过 1.2 亿人每天佩戴 Apple Watch 或 Fitbit             │
│                                                                 │
│   😕 但 90%+ 的用户只看了步数和心率 — 然后就不知道还能做什么       │
│                                                                 │
│   📊 一个用户 2 年的 Apple Health 数据超过 400MB                  │
│     包含: 心率、HRV、睡眠阶段、血氧、活动能量、呼吸率…             │
│                                                                 │
│   ❌ 这些数据之间存在深刻的关联 — 但没有工具能帮用户发现           │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 Users' Pain Points: 用户的真实痛点

| # | 痛点 | 用户原话 (User Voice) |
|---|------|----------------------|
| 1 | **数据太多，洞见太少** | "我每天戴着 Apple Watch，但除了关掉久坐提醒，我根本不知道怎么用那些数据" |
| 2 | **指标之间看不懂关联** | "我睡够了 8 小时但早上还是很累 — HRV、心率、睡眠阶段能告诉我为什么吗？" |
| 3 | **趋势变化发现太晚** | "医生说我长期压力大，但我手机里明明有一整年的心率数据，却没人帮我分析" |
| 4 | **现有 App 都是静态图表** | "Fitbit 给我 20 张图表但我看不懂，我只需要有人告诉我：这正常吗？该做什么？" |
| 5 | **个性化建议稀缺** | "网上都是泛泛的'每天走 10000 步'，但我的膝盖有问题 — 我需要适合我的建议" |

### 2.3 Target Users: 谁需要这个产品？

```
Primary Users (核心用户)
├── 🏃 健康意识型消费者 (25-45岁，已有可穿戴设备)
│      → 想要更深度的健康洞察，但不需要医学学位才能看懂
│
├── 🧘 压力管理 / 慢性疲劳人群
│      → "我总觉得累" → 想知道数据能否解释原因
│
└── 🏋️ 健身爱好者
       → 想了解训练对身体的实际影响（恢复状态、HRV 趋势）

Secondary Users (扩展用户)
├── 👴 慢性病管理 (50+ 岁，医生建议监测)
└── 👨‍⚕️ 初级保健医生 (快速了解患者长期趋势)
```

### 2.4 Project Scope: 我们要做什么（12 周）

```
Week 12 交付范围:

  ✅ Core Feature 1: 多源健康数据导入
     • Apple Health Export (XML) 解析
     • Fitbit Web API 接入
     → 统一数据 Schema，覆盖 10+ 生理指标

  ✅ Core Feature 2: AI 健康分析引擎
     • 自然语言查询: "我最近睡得怎么样？"
     • 时序趋势分析: 自动检测异常变化
     • 跨指标关联: "睡眠对我的心率有什么影响？"

  ✅ Core Feature 3: 对话式交互界面
     • Chat-first UI（类似 ChatGPT）
     • 关键指标 Dashboard 面板
     • 每周健康摘要自动生成

  ⏳ Out of Scope (留到未来):
     • 实时可穿戴设备连接
     • Android / 移动端原生 App
     • 多用户 / 家庭模式
```

### 2.5 Objective: 成功的标准

> 让一个普通的可穿戴设备用户，在 **5 分钟内**从「导入数据」到「获得一个他以前不知道但有意义的健康洞察」。

Measurable:
- 成功解析 ≥2 种数据源 (Apple Health + Fitbit)
- Agent 能回答 ≥6 种不同类型的健康查询
- Demo 时可以展示一个真实的、有情感共鸣的个人数据故事

### 3.2 Landscaping: 竞品格局

| 产品 | 做什么 | 缺失什么 |
|------|--------|----------|
| **Apple Health** | 数据聚合 + 基础图表 | ❌ 没有自然语言交互 ❌ 不做跨指标关联分析 ❌ 没有个性化建议 |
| **Fitbit Premium** | Ready-to-consume 健康报告 ($9.99/月) | ❌ 报告模板化，不能自由提问 ❌ 不解释「为什么」❌ 不支持其他设备 |
| **Whoop** | 专业级 strain/recovery 评分 ($30/月) | ❌ 贵！❌ 锁定自家硬件 ❌ 面向运动员，普通人用不上 |
| **Oura** | 环形设备 + sleep/readiness 评分 ($6/月) | ❌ 需要额外买 $300+ 戒指 ❌ 不做自然语言问答 |
| **Bevel** | HRV + 恢复追踪 | ❌ 指标单一 ❌ 不跨设备 |
| **ChatGPT** | 可以描述症状并问 | ❌ 无法接入你的真实健康数据 ❌ 回答泛化，不个性化 |

**Competitive Advantage (为什么我们能赢)**:

1. **Device-Agnostic**: 不强制买特定硬件 — 导入你已有的数据即可
2. **Conversational AI**: 不像 Fitbit 给你一堆图表 — 你直接问，AI 告诉你答案
3. **Cross-Metric Correlation**: 唯一能把「睡眠→HRV→心率→活动」关联起来的产品
4. **Privacy-First**: 数据本地处理，不上传云端

### 3.4 Market Timing: 为什么是现在？

- ✅ **2025 Apple Health 开放更多数据导出选项** — 数据获取门槛持续降低
- ✅ **Google PHA 发布 (Sep 2025)** — 验证了 AI Agent × 健康的可行性
- ✅ **LLM 成本骤降** — GPT-4o / Gemini Flash 让 AI 分析变得经济可行
- ✅ **用户健康意识 post-COVID 持续上升** — "我的身体到底在发生什么" 成为主流需求
- ✅ **可穿戴设备渗透率突破临界点** — 足够多的用户已经有了数据，只是不会用

### 4.3 Why It's Better: 关键差异化

| | 现有方案 | HealthPulse |
|------|------|------|
| **交互方式** | 被动看图 | 主动对话 — AI 主动发现并向你"汇报" |
| **分析深度** | 单指标趋势线 | **跨指标关联** — "睡眠变差 → HRV 下降 → 静息心率上升" |
| **知识来源** | 通用健康小贴士 | **个人数据 + 医学文献** 双重 grounding |
| **设备兼容** | 锁定生态 (Apple vs Fitbit) | **Device-Agnostic** — 导入任何设备数据 |
| **隐私** | 数据上云 | **本地处理** — 只发统计摘要给 LLM |
| **个性化** | "你本周平均睡眠 6.5h" | "你的睡眠比上两周少了 1 小时，而且入睡时间推迟到凌晨 1 点" |

```
⏱ 3 分钟演示流程:

[00:00-00:30] 数据导入

[00:30-01:30] 主动洞察
   → AI 主动推送: "我注意到一个有趣的模式 — 你的周三心率

[02:30-03:00] 个性化建议
   → AI: "基于你的数据趋势，这里是一个为期 2 周的恢复计划。

   → 🎤 "这就是 HealthPulse — 让你的身体数据，终于开口说话。"

⏱ 结束。
```
